# ADR-003：以账号密码熵缓解 F3（保留“账号 + 密码”配对）

- 状态：**已决策**
- 日期：2026-11-06
- 关联：ADR-001（OPAQUE / Argon2id KSF）、安全审计 F3 / F9 / F13

## 1. 背景与问题

审计 F3 指出：OPAQUE 的 `ServerSetup` 由共享账号密码确定性派生。攻击者只要观察到
一次握手，就能离线验证密码猜测（约 2 次 Argon2id / 猜测 / 核）。若密码是低熵的
用户自选口令，这条离线路径等价于把口令哈希暴露给监听者。

替代方案“随机 `ServerSetup` + 带外配对码”能消除该离线路径，但会改变产品形态：
owner 明确选择保留“账号 + 密码”的入门流程，不引入配对码。

## 2. 决策

1. **保留“账号 + 密码”配对模型**；不实现随机 `ServerSetup` 配对（F3 原提案不采纳）。
2. 把抗离线猜测的责任放到**密码熵**上：
   - Windows 壳在**创建/修改**账号时强制：≥12 字符、拒绝明显弱模式
     （同字符、连续序列、常见密码、与账号同名），粗估熵低于 60 bit 亦拒绝；
   - 提供“生成强密码”：160-bit 随机、Crockford base32（无 I/L/O/U）、
     `XXXX-XXXX-...` 分组，并要求用户保存后用于其他设备。
3. core 保持兼容：短密码/历史密码只**告警**、不拒绝（`parse_cfg` 的
   `password_weakness_reason`）。重复登录已有账号不套用创建时的强度门槛。

## 3. 理由

- 没有带外通道时，“抗离线猜测强度 == 密码熵”。确定性 `ServerSetup` 本身不是
  漏洞；它只是把密码猜测搬到离线，而高熵密钥让穷举不可行。
- Argon2id 当前实测约 **80~120 ms/猜测/核**（每次猜测约 2 次 KSF）。对强密钥它
  只是额外成本；对弱口令，决定因素是口令空间 2^n，慢哈希无法弥补。
- 因此无需为了 F3 牺牲 onboarding 体验；把约束放在“创建/修改”时刻最有效，
  且不破坏既有部署。

## 4. 后果

- **兼容**：已有短密码继续可用（core 告警）；升级不会阻断老用户启动。
- **用户责任**：新账号必须自选 ≥12 字符的强密码，或使用生成器；必须自行保存
  该密钥，后续设备输入同一账号密码才能配对。密码丢失无法找回。
- **F3 状态**：在“用户使用生成器/强密码”前提下接受残余风险；这不是密码学层面
  的修复，而是把攻击成本提高到不可行。若未来允许任意弱密码，F3 会重新成立。
- **F9（首次连接 MITM）仍开放**：盲信 TLS + 自动 TOFU 仍需首次指纹确认对话框，
  与本次熵缓解正交，留待后续。
- **F13（KEK 存于 OS keystore）仍开放**：本次不改密钥存储模型。

## 5. 验证

- 壳侧纯函数单测覆盖强度规则与 160-bit 生成器格式；创建/修改路径有门槛，
  登录/历史账号不阻断。
- core 单测验证短密码仍被接受，且命中 `password_weakness_reason` 告警路径。
- ADR-001 的 Argon2id KSF 保持不变；本决策不引入新依赖或协议变更。
